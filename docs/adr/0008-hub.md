# ADR-0008: MYELIN Hub — localhost 전용, 사람의 클릭만 쓴다

- 상태: Accepted
- 일자: 2026-10-18
- Phase: P6

## 맥락
Hub는 처음으로 **노트를 고치는** 구성요소다 (verified 승격). ADR-0005는 "노트는 절대 수정하지 않는다"고 정했고,
명세 §3은 "verified 승격은 사람만, Hub Review Gate가 유일한 승격 경로"라고 정했다.
또 Hub는 브라우저에서 돌아가므로, 사용자가 다른 웹사이트를 보는 동안 그 사이트가 Hub를 조작하는 경로를 막아야 한다.

## 결정

### 1. 배치
- `myelin-hub --vault <경로>`: FastAPI + uvicorn, **loopback(127.0.0.1·::1·localhost)만 바인딩**. 다른 주소면 exit 2.
  Team 모드(인증)는 v1.0 이후. 시작만으로는 Vault에 아무것도 쓰지 않는다.
- Hub는 `myelin_core` 를 그대로 쓴다. 판단 로직(승격·반려·온보딩·git)은 core에 두고 CLI와 공유한다:
  `myelin_core.onboarding`(CLI `init`/`add-domain` 과 같은 코드), `myelin_core.review`, `myelin_core.gitops`.
- Hub는 MCP 색인(`.myelin/index.db`)을 쓰지 않는다 — 색인 생성도 Vault 쓰기이기 때문.

### 2. 사용자 행위 없는 쓰기 0
| 방어 | 내용 |
|---|---|
| Host 검사 | Host 헤더가 loopback 이름이 아니면 403 (DNS rebinding) |
| 쓰기 = POST만 | GET은 읽기 전용. 테스트가 모든 GET을 호출하고 Vault 전체(.git 포함) 해시를 비교 |
| 의도 헤더 | POST는 `X-Myelin-Intent: user` 필수 — 화면의 버튼 핸들러만 붙인다. 다른 출처는 CORS preflight에서 막힘 |
| Origin | POST의 Origin이 Hub 자신과 같아야 함 |
| JSON만 | `text/plain` 폼 POST(CORS 단순 요청) 거부 |
| 헤더 | CSP `default-src 'self'`, `frame-ancestors 'none'`, no-store |
| 경로 목록 | 쓰기 API 목록을 테스트가 고정 — 새 POST를 만들면 검토 없이 통과하지 못한다 |

### 3. Review Gate (ADR-0005 노트 불변 규칙의 유일한 예외)
- 바꾸는 것은 frontmatter의 `status`·`reviewed` **두 키뿐**. ruamel round-trip으로 다른 키·순서·주석 보존, **본문은 바이트 그대로**
  (BOM·CRLF는 LF로 정규화). 결과를 다시 파싱해 id·본문이 같은지 확인한 뒤 쓴다.
- `origin` 은 바꾸지 않는다 — 사람이 검토해도 AI가 쓴 것이라는 출처는 남는다 (승격률 지표의 근거).
- 승격: `00_Inbox/**` 의 노트는 첫 번째 Vault Domain의 `10_Domains/<ID>/` 로 이동, 그 밖은 제자리.
  반려: `status: deprecated` 로 `99_Archive/rejected/` 에 이동. **삭제하지 않는다.**
- 요청은 화면에 표시된 노트의 `id` 를 함께 보낸다. 파일의 id와 다르면 거부 (보지 않은 노트를 승격하지 않는다).
- 거부(fail-closed): Vault 밖·심볼릭 링크·지식 노트가 아닌 경로, 깨진 frontmatter, draft/unverified 아닌 상태,
  Vault Domain이 없는 노트, 이동 대상 존재, `confidential + share`, **미검증 AI 노트를 링크하는 노트**
  (승격하면 doctor의 fail-closed 규칙 위반이 되므로 그 노트를 먼저 검토하게 한다).

### 4. git
- 승격·반려는 **반드시 commit** 으로 남는다 (명세 §3: promote → git commit). Vault가 git 저장소가 아니면 승격을 거부하고
  Settings의 "로컬 git 시작"(또는 온보딩의 기본 체크)을 안내한다.
- commit은 Hub가 바꾼 경로만 담는다 (`git commit -- <paths>`). 사용자가 따로 고치던 파일은 섞이지 않는다.
- commit이 실패하면(훅 거부 등) 파일 변경을 되돌린다.
- push·remote·fetch는 하지 않는다. 이름/이메일이 git 설정에 없을 때만 Vault 주인으로 채운다.
- 설정 변경·Domain 추가도 저장소가 있으면 commit 한다.

### 5. 화면에서 바꿀 수 있는 것
- 설정: `level`, `mcp.write_drafts` 만. **`llm.route`(기밀 → 로컬 경계)는 Hub에서 바꿀 수 없다** — 파일을 직접 고쳐야 한다.
- Pack 편집기: 검증만 한다(순수 함수). Pack은 데이터이고 Pack 저장소에서 git으로 관리한다 (ADR-0004).

### 6. 웹
- Vite + React 18 + TypeScript + Tailwind 3, `design/dist/tailwind.preset.js` + `tokens.css` + `components.css` (ADR-0007).
- 색은 토큰만 — `design/build.py --lint` 가 `packages/myelin-hub/web/src` 를 검사한다.
- 노트 본문은 HTML로 렌더링하지 않고 텍스트로 보여 준다 (XSS 표면 없음).

## 결과
- 사용자가 버튼을 누르지 않으면 Vault는 바뀌지 않는다 — API 테스트와 Playwright e2e가 Vault 해시로 확인한다.
- 모든 승격·반려는 `git log` 로 추적·되돌릴 수 있다.
- 미해결: Guard 차단 이벤트 표시(Guard가 아직 이벤트를 기록하지 않음), 다크 모드, Team 모드 인증.
