## 설계 변경 — ADR-0002 Rev 2 (현행 문서 재대조 결과)
1. **Guard 주 장치를 Vault 안으로.** 플러그인은 사용자 단위로 켜져 *모든 프로젝트*에서 Hook이 돈다.
   Rev 1 설계("Vault 루트 미지정 = 차단")였다면 Brian의 다른 코드 저장소 쓰기까지 막혔을 것이다.
   - 이제 Vault의 `.claude/settings.json` Hook이 그 Vault에서만, 플러그인 설치 여부와 무관하게 동작한다.
   - 플러그인 Hook은 다른 프로젝트 세션이 Vault로 쓰려는 경우만 잡는다.
2. **읽기도 차단.** Claude가 노트를 읽는 순간 내용이 Anthropic으로 전송된다.
   `40_IP/`(candidates 제외)와 `classification: confidential` 노트의 Read를 막는다 (`llm.route` 기본값 local).
   README Privacy model과 장치가 처음으로 일치했다. 이전 CLAUDE.md의 "40_IP는 읽기만"은 "읽지 않는다"로 수정했다.
3. **Level별 쓰기 허용** — 명세의 Phase-gated Autonomy를 문구가 아닌 장치로 구현했다.
4. **다층 방어** — `Edit` deny가 Bash 리다이렉트·sed·tee 대상까지 막는다. 파괴·네트워크 명령은 deny, `myelin doctor/stats` 만 allow, 그 외 Bash는 매번 사람 승인.

## Guard 검증 (실제 Hook처럼 별도 프로세스로 실행)
- Level 게이트 20개 경로 · 상대경로 · `..` 탈출 · Vault 밖 쓰기 · 심볼릭 링크(안→밖, 밖→안).
- 잘못된 입력 8종 × (Vault Hook, 플러그인 Hook) → 모두 exit 2.
- 비-Vault 프로젝트 → 간섭 없음 · 40_IP·confidential 읽기 차단 · route가 claude면 허용.
- 알 수 없는 level 값 → Level 0으로 처리.
