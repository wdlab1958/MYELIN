# 지식 관리 지침 — 무엇을 기록하지 않는가

> 적용 대상: One Cycle Dev. Framework 를 수행하며 MYELIN 에 지식을 남기는 개발자·운영자 전원. (WBS 2.5.5 · 2026-11-26)
> MYELIN 은 고객에게 파는 상품이 아니다. One Cycle Dev. Framework 에서 생긴 정보 자산을 개발자와 운영자가 관리하는 **개인 지식 관리 서비스**다.

## 1. 왜 필요한가
MYELIN 의 Skill(`/ingest`·`/distill`·`/interview` …)은 Claude Code 를 거친다. `classification: confidential` 노트와 `40_IP/**` 는 로컬 모델 세션(`MYELIN_LLM=local`)에서만 읽히지만, 그 밖의 노트 내용은 외부 LLM 세션에 올라갈 수 있다. 그래서 **애초에 적지 않는 것**이 유일하게 확실한 통제다.

## 2. 절대 기록하지 않는 것

| 구분 | 예 | 대신 이렇게 |
|---|---|---|
| **고객 식별 정보** | 고객사 이름·약칭·프로젝트 코드, 담당자 이름·연락처·이메일, 시스템·호스트·도메인 이름, IP 주소, 계약 번호 | 고객 유형(금융·공공·제조·플랫폼)과 자리표시자(`<고객A>`, `<호스트1>`, `<외부IP>`) |
| **고객 코드** | 고객 저장소의 소스 코드, 설정 파일, 쿼리, 로그 원문, 스택 트레이스 | 문제의 *구조*를 말로 적거나, 직접 다시 쓴 최소 예시(30줄 이하, 고객 식별자 없음) |
| **자격증명** | 비밀번호, API 키, 토큰, 개인키, 접속 문자열, 세션 쿠키 | 적지 않는다. "자격증명이 설정 파일에 평문으로 있었다"는 사실만 |
| **개인정보** | 주민등록번호, 전화번호, 개인 이메일 | 적지 않는다 |
| **고객에게 받은 문서** | 진단 대상 산출물, 내부 규정, 구성도 | 원본은 프로젝트 보관소에만. MYELIN 에는 일반화한 교훈만 |

다른 플랫폼이 넘기는 초안(`source_platform`)과 findings 파일에도 같은 규칙이 적용된다. 넘기는 쪽에서 먼저 지운다.

## 3. 기록해도 되는 것
- 고객을 알아볼 수 없게 일반화한 **교훈**과 **판단 기준**("관리자 경로의 인증 통제는 일반 사용자 경로와 따로 점검한다").
- 공개 표준의 항목 번호(ISO/IEC 27001 Annex A, MITRE ATT&CK 전술·기법 id, CWE).
- 우리 도구의 사용법, 점검표, 직접 만든 예시.
- `simulated: true` 인 모의 결과 — 단, 사실로 인용하지 않는다.

## 4. 장치 — 지침을 돕는 결정적 검사 (ADR-0017)
사람이 1차 통제이고 아래 장치는 보조다. 장치가 통과시켰다고 기록해도 된다는 뜻이 아니다.

| 시점 | 동작 |
|---|---|
| MCP `write_draft`, `myelin onecycle import-findings` | 자격증명·주민번호·고객명 → 초안을 만들지 않는다 |
| Hub 승격(Review Gate) | 위 항목 → 승격 거부. 긴 코드 블록·IP·내부 URL → 확인 창에서 "고객 정보가 아님"을 확인해야 승격 |
| Vault 커밋(pre-commit) | 00_Inbox 밖의 노트에 위 항목이 있으면 커밋 거부 |
| Commons 공개 | 비식별 스캔 + 가드. 하나라도 걸리면 공개 불가 |

**고객명 목록 등록(필수, 프로젝트 시작 시):**
```bash
mkdir -p ~/Vaults/me/.myelin
printf '%s\n' '<고객사 이름>' '<약칭>' '<프로젝트 코드>' >> ~/Vaults/me/.myelin/customer-names.txt
myelin guard scan --vault ~/Vaults/me        # 기존 노트 점검. BLOCK 이 있으면 exit 1
```
이 목록 자체가 고객 정보다. `.myelin/` 은 git 에 올라가지 않는 런타임 폴더이며, 목록을 Vault 의 다른 곳이나 저장소·Commons 에 두지 않는다. 임계값과 추가 패턴은 `90_System/infoguard.yaml` 에 둔다(예: `max_code_block_lines: 20`).

## 5. 실수로 적었을 때
1. 노트에서 해당 내용을 지운다. 자격증명이면 **먼저 그 자격증명을 폐기·교체**한다(노트에서 지우는 것으로는 부족하다).
2. 이미 커밋했다면 이력에도 남아 있다. Vault 는 push 하지 않는 로컬 저장소이므로(ADR-0014) 이력 정리는 Vault 소유자가 한다. Commons 에 올라갔다면 챔피언에게 즉시 알린다.
3. 같은 일이 반복되지 않게 고객명 목록·패턴을 보강한다.

## 6. 책임
- 기록한 사람이 내용에 책임진다. AI 초안도 승격한 사람이 읽고 확인한 것이다(ADR-0009).
- 팀 챔피언은 Commons PR 에서 한 번 더 본다(ADR-0010).
- 이 지침의 용어·범위는 법무·보안 담당의 검토를 받지 않았다(검토 전).
