# 회고 — MYELIN P0 ~ P8 (v1.0)

- 일자: 2026-10-18 · 방식: Claude Code 단계별 구현 (Phase Gate + 사람 승인 "GO Pn")
- 규모: Python 약 5,600줄(core 4,000 · CLI · MCP · Hub API) · TypeScript 1,560줄 · 플러그인 스킬 7종.
  테스트 코드 약 4,000줄, pytest 480건 이상(Playwright e2e 포함). 커밋 23개.

## 1. 잘 된 것 — 다음에도 그대로
- **Gate를 코드로 먼저 쓰기.** 각 Phase의 첫 Task가 `scripts/gate.py` 검사 추가였다. 기준이 문서가 아니라 실행 가능한 검사로 먼저 서 있어서,
  "다 됐다"의 정의가 흔들리지 않았다. 지난 Gate를 언제든 다시 돌릴 수 있게 만든 것(회귀 Gate)이 P5·P6·P8 변경에서 실제로 문제를 잡았다.
- **fail-closed를 테스트 형태로.** 사용자 행위 없는 쓰기 0(Vault 해시 비교), 공개 차단 48조합, 경로 탈출·링크·제어 문자.
  "막는다"는 주장마다 그것을 깨려는 테스트가 있다.
- **core 하나, 얇은 어댑터 여럿.** CLI·MCP·Hub가 같은 core를 쓴다. 온보딩은 CLI `init` 과 Hub 마법사가 같은 함수다.
  Guard 판정을 MCP `write_draft` 가 재사용한다. 규칙을 두 곳에 구현하지 않았다.
- **Pack = 데이터.** P7에서 `org.incident-response` 를 코드 변경 없이 추가했다. 원칙이 실제로 지켜졌다는 증거.
- **독립 검토.** P6에서 구현을 보지 않은 검토 에이전트가 Review Gate의 문제 6건을 찾았다 (stage 누수, CRLF 변형, 임시 파일 링크,
  glob pathspec, 대상 링크, 제어 문자). 스스로 쓴 테스트로는 하나도 잡지 못했던 것들이다 → 위험한 변경은 다른 눈이 본다.

## 2. 어려웠던 것 — 원인과 교훈
| 사건 | 원인 | 교훈 |
|---|---|---|
| 명세 색 4개가 명세 자신의 대비 기준(4.5:1)을 어김 (P5) | 명세 작성 때 대비를 계산하지 않음 | 가드레일이 있으면 명세 값도 검사 대상이다 |
| `design/dist/` 가 `.gitignore` 의 `dist/` 에 걸림 (P5) | 넓은 무시 규칙 | 생성물을 커밋한다면 CI에서 처음부터 검사 |
| MCP SDK가 2.x로 바뀌어 API 이름이 달라짐 (P4) | 기억 속 API를 가정 | 설치된 패키지 소스를 먼저 읽고, 버전 범위를 고정 |
| 한글 경로가 git 출력에서 8진수로 인코딩됨 (P6) | `core.quotepath` 기본값 | 파일 이름을 git으로 다룰 때는 항상 `-z` |
| CSP가 Playwright의 `wait_for_function` 까지 막음 (P6) | 보안 정책이 테스트 도구에도 적용 | 오히려 CSP가 실제로 동작한다는 증거 — locator 기반 대기로 |
| 테스트 하나가 실제 uvicorn을 띄워 멈춤 (P6) | 실행부를 대체하지 않은 테스트 | 서버를 띄우는 진입점은 테스트에서 반드시 대체 |
| Pack 템플릿이 Obsidian에서 **코드로 실행**될 수 있음 (P8 위협 모델) | "Pack은 데이터"라고 믿었지만 Templater가 그 데이터를 실행 | 데이터를 실행하는 하류가 있는지 확인 → 허용 목록 |
| 같은 PC의 다른 사용자가 localhost Hub를 읽을 수 있음 (P8) | loopback = 안전이라는 가정 | localhost 서비스도 인증 토큰 |
